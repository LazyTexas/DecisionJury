# DecisionJury 前端 UI 彻底重构 · 多风格方案选型

> 本文档由角色 E（接手前端）编写，面向全员/答辩评审，用于在**彻底推翻重做**的前提下，从多套差异化风格中选型。
> 本文档只做**风格选型**，不写最终代码。确认方向后再进入实施；实施仍全程可逆（见 §7）。
> 本方案覆盖整个 Web 应用（工作台/新建/对话/判决书/历史/观察清单），非局部微调。

---

## 0. 先说结论（可选哪套）

| 方案 | 一句话定位 | 核心记忆点 | 答辩观感 | 开发成本 |
|---|---|---|---|---|
| **A 法庭裁判庭** | 把决策做成一场"庭审" | 三方角色对垒 + 判决书卷宗 | 最契合品牌、仪式感强、庄重 | 中 |
| **B AI 指挥台** | 把多 Agent 流程做成"流程图" | 动态节点点亮 + 连线流动 | 最"高科技"、架构感最强、一张图讲清编排 | 高 |
| **C 极简信件/笔记** | 判决书=写给你的信 | 杂志/信件排版 + 两栏批注 | 最耐看、最"产品"、克制理性 | 低-中 |
| **D 数据仪表板** | 用数据卡片说话 | 环形预算占比 + 风险三色 + 置信度仪表 | 最"数据化"、最适合证明工具结果 | 中 |
| **E 互动剧本(可选项)** | 用户当"陪审团"逐步推进 | 剧情式演流程 + 分支 | 最强互动、演示记忆点强 | 高 |

> 推荐组合：答辩优先选 **B 或 A**（视觉冲击 + 一眼讲清多 Agent 编排）；若更看重"产品成熟/耐看"选 **C**；更看重"数据/工具证明"选 **D**。下面每套都给出完整方案与取舍。

## 1. 方案 A · 法庭裁判庭（庄重·仪式感）

### 1.1 理念
用真实"法庭"隐喻承载产品：正方 = 控方/原告方，反方 = 辩方，法官 = 裁决，RAG 证据 = 呈堂证供，工具结果 = 鉴定报告，判决书 = 正式判决文书。**"你不是在问 AI，而是让 AI 开庭。"**

### 1.2 视觉
- 底色：暖白/米色羊皮纸质感 + 深酒红/墨蓝点缀（庄重）。
- 字体：标题衬线（如 Noto Serif SC/思源宋体），正文黑体；竖向大标题增强仪式感。
- 元素：法槌、天平、印章、案卷编号、带编号的"卷宗页码"。

### 1.3 布局骨架
```text
┌──────────────────────────────────────────┐
│ 品牌·印章   [新案] [案卷] [历史]   用户  │
├──────────────────────────────────────────┤
│  案件卷宗（左 1/3）  │  庭审主区（右 2/3） │
│  ·案号 / 状态        │  上方：法官席位居中  │
│  ·角色席位清单       │  左：正方 · 右：反方 │
│  ·呈堂证据列表       │  正文：控/辩两栏对垒  │
└──────────────────────────────────────────┘
```
- 判决书页 = 一份"判决文书"：编号、法院名（DecisionJury 冷静裁判庭）、案由、判决主文、落款法官、盖章。
- 对话页 = "庭审记录/问讯笔录"，一句句带时间戳。

### 1.4 核心记忆点
- **庭审式对垒**：正方/反方以"席位"左右对立呈现，中间是法官；RAG 证据与工具结果作为"当堂呈上的证物"弹出。
- 判决书"盖章"动效：裁决生成时盖上"D 认为…"之印章，仪式感拉满。

### 1.5 效果
- 极度契合 "DecisionJury" 品牌名，答辩记忆点强、有情绪感染力。
- 把"多 Agent 辩论"讲成"庭审"，观众秒懂产品价值。

### 1.6 风险/取舍
- 深色/羊皮纸风在明亮答辩投影需控制对比度；衬线字可读性需调字号。
- 仪式感可能稍"重"，需避免与"克制理性"的产品基调冲突。开发成本中。

## 2. 方案 B · AI 指挥台(动态流程图) · 高科技

### 2.1 理念
把整套多 Agent 工作流当作一条**生产线/管道**：输入解析 → RAG → 成本工具 → 正方 → 反方 → 冷静期 → 法官，做成一张可互动的"流程地图"。**"一张图讲清 Agent 编排。"**

### 2.2 视觉
- 深色底 + 霓虹渐变（靛蓝→紫→青），玻璃拟态卡片、发光节点、柔和光晕。
- 节点连线带流动动画；不同 Agent 用不同发光色（正方绿/反方红/法官靛蓝/工具青/RAG 紫）。

### 2.3 布局骨架
```text
┌──────────────────────────────────────────┐
│  [导航: 决策台/新案/历史/观察]            │
├──────────────────────────────────────────┤
│        ★ 流程地图（页面主体）★            │
│  输入解析→RAG→成本※正方→反方→冷静期→法官  │
│   (节点按执行点亮, 连线流动, 可点击展开)    │
│                                          │
│  顶部: 裁决徽标 + 置信度仪表               │
│  下方: 证据卡片 + 工具结果 + 判决书正文     │
└──────────────────────────────────────────┘
```
- 判决书页主体是这张流程地图 + 底部证据/判决内容。
- 对话页保留聊天，但顶部同步显示"当前管道"进行到哪一步。

### 2.4 核心记忆点
- **动态流程图**：辩论执行时节点依次点亮、连线流动——答辩时直接把"多 Agent 编排"可视化成一个可演示的架构图。
- 工具调用是"节点"，清晰展示 cost_analyzer / cooling_reminder 何时被调用。

### 2.5 效果
- 最"AI 高科技"，一张图就等于架构图，答辩讲"多 Agent + RAG + MCP"最省力、最直观。
- 很符合课程对"Agent 编排/可观测"的展示需求（trace 可视化）。

### 2.6 风险/取舍
- 动效开发成本高、需控制性能；深色在白天投影要注意亮度；过度炫技可能喧宾夺主。需配新手/降级解释。

## 3. 方案 C · 极简信件/杂志风 · 克制耐看

### 3.1 理念
把"决策"做成一份**写给用户的信/一页冷静决策笔记**：大量留白、清晰的正文朗读感、几乎无边框。类 Notion / Linear / Medium 的编辑质感。**"最简洁，也最像产品。"**

### 3.2 视觉
- 底色：暖白；文本深灰；强调色极收敛（仅裁决/风险用语义红绿）。
- 字体：大字号正文（阅读感）、细网格、极细分隔线/边框、大量留白。
- 无卡片堆叠，正文自然分层。

### 3.3 布局骨架
```text
┌──────────────────────────────────────┐
│  [顶部极简导航]  决策台 / 新案 / 历史  │
├──────────────────────────────────────┤
│   一封信/笔记（居中窄栏, 单栏流式）      │
│   标题 ▶ 摘要 ▶ 正方(栏注) ▶ 反方(栏注)│
│   ▶ 证据(脚注引用) ▶ 裁决 ▶ 下一步     │
│   （正文朗读感, 引用像脚注, 栏注像批注)  │
└──────────────────────────────────────┘
```
- 判决书 = **一封信**："写给正在纠结的你"；两栏批注式正反方。
- 对话 = 轻量聊天流；工作台 = 一个干净的"案件列表+最近决策"。

### 3.4 核心记忆点
- **信件式判决书**：把"建议"写成温和、可读、克制的信，贴合产品"不替你做决定、给可解释建议"的定位。
- 极强可读性，答辩文案天然耐看。

### 3.5 效果
- 最耐看、最像成熟 SaaS/产品，体现"理性、克制、可解释"的品牌气质。
- 通过"编号引用脚注"呈现 RAG 证据与工具结果，克制但不失严谨。

### 3.6 风险/取舍
- 视觉冲击弱，答辩开场可能显得"平淡"；需靠文案与信息层级取胜。开发成本低-中，最适合"求稳、够用、耐看"。

## 4. 方案 D · 数据仪表板 · 用数据说话

### 4.1 理念
把"证据"做成**数据卡片/仪表**：预算占比环形图、风险三色等级、RAG 相关性条形、判决置信度仪表、冷静期倒计时。**"用数字为决策背书。"**

### 4.2 视觉
- 现代 SaaS 仪表板：浅色主区 + 卡片化 + 各类 Mini 图表（环形/条形/仪表），强调数据密度。
- 语义色：风险 low/medium/high 三色、裁决标签。

### 4.3 布局骨架
```text
┌────────────────────────────────────────┐
│ [导航]  决策台 / 新案 / 历史 / 观察清单 │
├────────────────────────────────────────┤
│  顶部: 裁决徽标 + 置信度仪表 + 风险等级  │
│  中部: 证据网格卡(4~6张)                │
│    ·预算占比环形 ·成本风险三色           │
│    ·RAG相关性条形 ·冷静期倒计时          │
│  下部: 决文正文(正方/反方/后续动作)       │
└────────────────────────────────────────┘
```
- 判决书页 = 一个"决策数据板"，顶部仪表 + 中部证据网格 + 下部正文。
- 工作台 = 案件 KPI 看板（进行中/待辩论/已判决/观察中 数量）。

### 4.4 核心记忆点
- **数据卡片网格**：预算占比环形图、风险三色、置信度仪表、冷静期倒计时——把 MCP 工具结果与"冷静期"这类含数值产出做成可视化证据。
- 答辩时可"用数字说话"，工具结果展示极强。

### 4.5 效果
- 最"数据化/工具感"，特别适合证明 cost_analyzer / cooling_reminder 的产出与"冷静期"闭环。
- 信息密度高、专业，但自然语言观点（正反方论述）呈现相对弱。

### 4.6 风险/取舍
- 偏"后台工具"，少一点"决策助手"的温情；对自然语言观点不如 C/A 有感染力。开发成本中。

## 5. 方案 E · 互动剧本 · 陪审团体验（可选）

### 5.1 理念
把整条流程做成可交互的"剧本/游戏"：用户是**陪审团**，逐步阅读案情 → 听取控方 → 听取辩方 → 看证物(证据/工具) → 在法官裁决前"自己先投一票" → 系统公布判决书。
### 5.2 视觉
- 剧情化分幕、卡片推进、底部"下一步"引导；配色柔和、插画式头像（正方/反方/法官）。
### 5.3 核心记忆点
- **"你先投一票，再看法官怎么判"**：极强互动与记忆点，答辩演示印象深刻。
### 5.4 效果
- 互动性最强、演示记忆点拉满，能引导用户理解"正反辩论—证据—裁决"的完整逻辑。
### 5.5 风险/取舍
- 开发成本最高、流程改造成本最大；互动可能分散对"技术含量"的注意力。适合作为演示加分项而非主方案。

## 7. 彻底重构的可逆性（多个方案同样适用）

推翻重做≠不可逆。建议采用"**平行应用 + 开关切换 + git 分支**"三层保障：

1. **平行应用**：新版作为独立应用壳/目录（如 `src/v2/` 或独立 `frontend-v2/`），旧版`frontend/` 完整保留不删。用一个开关（`VITE_APP=v2` 或构建产物分目录）选择启动哪版。**新/旧可同时存在、随时切换**。
2. **Git**：从 `dev` 切 `feature/frontend-revamp` 分支；给当前可运行版打 `fe/frontend-baseline` tag；按功能小 commit（可独立 revert）；通过 PR 合并；回退 = `git reset --hard fe/frontend-baseline`。
3. **契约/边界**：`types/index.ts`、`api/` 只增不改字段；确需新字段先与 B 对齐并更新 `docs/04_API.md`；不触碰 `backend/`、`rag/`、`mcp_tools/`（纯前端重构，风险隔离）。

> 结论：因为采用"平行应用 + 开关"，即使整套风格被否，**旧的稳定版始终原样可用**，新方案只是"挂在旁边"的候选项，评估不满意即可整体丢弃。
