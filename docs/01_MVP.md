# DecisionJury MVP

> 当前范围按团队最新决定调整：本次三周实训只交付购物决策（`shopping`）；时间决策（`time`）延后，不纳入本轮实现、验收或答辩完成度。代码核对基线为 `dev@53d70bc`，当前状态见 [里程碑](03_Milestones.md)。

## 1. 项目目标

5 人团队交付一个可运行的购物决策 Web Demo：将“买不买”的自然语言想法转为结构化案件，通过历史记录检索、规则计算和多 Agent 分工，给出可解释的辅助建议。项目不是法律意义上的裁判系统，不代替用户决定，也不保证消费结果。

## 2. 用户与痛点

面向预算有限、容易冲动消费、希望在购买前比较理由的学生等日常消费者。

- 不清楚价格与剩余预算的关系。
- 容易只注意收益而忽略已有替代品、闲置风险。
- 过去的后悔记录和复盘不容易进入下一次决策。
- 普通自由聊天难以稳定留下字段、证据和可追溯报告。

以上为项目设计动机，不是用户调研统计或已证明的改善效果。

## 3. 本次交付范围

| 能力 | 交付要求 |
|---|---|
| 案件与多轮对话 | 创建购物案件、补充/纠正信息、保存累计字段和消息 |
| 信息收集 | 至少获得商品名、价格、剩余预算，无未解决冲突后可分析；增强字段可缺失 |
| Agent 编排 | parser、正方、反方、法官；正反方独立陈述，无交叉反驳或二次回应 |
| 简化模拟法庭 | 四条结构化发言 `debate_events`，报告保留回放数据，一次性返回 |
| RAG | BM25 检索种子/用户历史，有命中时引用，无命中或失败时不编造 |
| 工具 | `cost_analyzer`、`decision_score`、条件触发的 `cooling_reminder` |
| 判决 | 本地规则选 `buy / delay / reject / alternative`；LLM 生成自然语言说明 |
| 结果与复盘 | 报告、trace、观察清单和反馈转历史；提醒落库已补齐导入，完整页面闭环待验收 |
| 工程与演示 | 本地启动、部署配置、隔离测试和真实页面操作记录 |

已有注册登录用于演示身份和用户表记录；不将其描述为完善的 JWT/权限体系。工具名带有 MCP，但当前是统一 Python 调用契约与独立 HTTP 入口，不宣称标准 MCP Server 传输和协议握手已交付。

## 4. 不纳入本次范围

- `time` 主流程、时间案件端到端演示；现有时间工具、样例与枚举保留，不因本次文档变更删除。
- 医疗、法律、投资、借贷、就业离职、亲密关系等高风险决策服务。
- 支付、下单、电商账号登录、全网比价、日历集成。
- 正反方多轮互相反驳、SSE/WebSocket、自主循环规划。
- 向量/混合检索、生产级访问控制、自动通知推送，均不作为当前完成能力。

后续要重新启动时间决策或其他新能力，应先修订范围和接口再开发，不能作为本轮 C/D/E 的遗留必做项。

## 5. 信息收集与建议边界

累计字段为 `product_name / price / purpose / monthly_budget_left / owned_alternatives / expected_usage_frequency / trigger_reason`。

最低字段是 `product_name / price / monthly_budget_left`，缺失或冲突时继续收集。`ready_for_debate` 可以与仍缺少增强字段并存，不得以 `missing_fields` 非空就强制继续追问。

C 根据历史字段、本轮提取和纠正生成 `merged_fields`；B 保存它。当前同名非空提取可覆盖旧值，纠正最后覆盖；不宣称绝对不会覆盖，也不宣称有跨轮置信度存储或三轮熔断。

输出使用“建议”“可以考虑”等辅助措辞。`confidence` 和决策评分是实现内的启发式值，不是经过校准的正确率。高风险标记在 C 产生，B 仍负责拒绝路径，详见 [SPEC](02_SPEC.md)。

## 6. 两个购物验收案例

### 6.1 预算压力与证据分析

创建：

```text
我想买一副1299元的降噪耳机，最近学习需要安静，预计每天使用，这次是刚需。
```

补充：

```text
本月预算还剩3000元，已有普通耳机。
```

检查商品价格保持 1299、预算为 3000；成本占比约 0.43、风险为 `medium`。在该规则输入下法官建议 `delay`，LLM 文案不做逐字断言。展示 RAG、工具、四条发言、报告与 trace。

该例会触发提醒路径；B 已修复 `Reminder` 导入。验收仍需核对数据库和页面记录，不能把 C 单独成功当作 B 存储成功。

### 6.2 多轮价格纠正

```text
想买一部手机，预算3000元
价格大概是2500元。
刚才价格说错了，不是2500，是2200。
```

检查价格由 2500 更新为 2200，预算保持 3000；达到最低字段即可分析。若用户在案件已完成后继续修改，必须遵守 B 路由的状态限制，不假设自动重新辩论。

## 7. 数据与证据

- 静态历史为演示种子，不是真实受访者数据；实际用户复盘通过 B 历史接口进入检索候选。
- 现有种子包含购物与时间两类，时间部分仅保留用于组件兼容，不算本轮产品交付。
- 不要求每次检索都命中；专门验收正常空结果与服务故障两种情况。
- 不提交密钥、数据库、向量产物、个人隐私或本地测试输出。

## 8. 完成定义

1. 两个购物场景能在隔离演示环境中完成，多轮状态和价格/预算不串值。
2. 四个 Agent 步骤、四条庭审事件、规则判决及证据/工具结果可展示。
3. RAG 命中、无命中、服务失败及 LLM 降级均有对应验证记录。
4. 检查 B 的提醒落库、观察清单查询和复盘写入历史，验收页面闭环。
5. 文档与实际契约一致；测试记录注明 commit、环境、命令和结果，mock 与真实 API 分开。
6. 代码经组员 review；演示版本和启动方式明确。不因代码合入就自动满足以上运行验收条件。

本轮文档同步不宣布 MVP 已全部验收完成，待验证项统一记在 [里程碑](03_Milestones.md) 与 [测试计划](05_TestPlan.md)。
