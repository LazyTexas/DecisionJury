> 本目录用于把「小学期实验报告」拆成可分工、可合并的 Markdown 章节。
> 当前章节内容已按 `dev@5abbc86` 的实际代码和测试结果完成，已生成：
> - `docs/report/DecisionJury_小学期实验报告.md`
> - `docs/report/DecisionJury_小学期实验报告.docx`

> Word 版已加入分级目录（目录域，打开或更新域时自动生成带页码目录）。

## 1. 为什么这样做

- 学校模板要求章节多、图/表/代码展示多，直接多人共写一个 Word 文件容易冲突。
- 项目本身是 5 人分工（A 前端 / B 后端 / C Agent / D RAG / E 工具与工程化），
  报告按模块拆分后，每个人只负责与自己模块相关的章节，Git 冲突少、合并容易。
- 每章节文件都标注了负责人、状态、素材来源和「待填写」占位符，
  队长可以随时通过 `docs/report/README.md` 的进度表检查完成情况。

## 4. 章节文件约定

每个 `sections/*.md` 文件开头都使用统一元信息块：

```markdown
> 负责人：xxx
> 状态：待填写 / 草稿 / 已完成
> 目标页数：约 X 页（Word 排版后）
> 素材：仓库内已有文件路径
```

正文中统一使用以下占位符，方便最后搜索清理：

- `【待填写：...】`：还没有内容，需成员补充。
- `【截图：...】`：需要插入图片/截图，Word 排版时替换。
- `【表格：...】`：需要补充表格数据。
- `【代码：...】`：需要插入关键代码片段。
- `<!-- TODO: ... -->`：HTML 注释，合并后不会显示，仅给成员提醒。

## 5. 单人开发 / 合并流程

### 5.1 拉取最新代码

```bash
git checkout dev
git pull origin dev
git checkout -b feature/report-<你的章节>
```

### 5.2 只写自己负责的章节文件

例如 A 写需求分析和原型图：

```bash
# 在 feature/report-<你的章节> 分支下编辑
docs/report/sections/02_需求分析.md
docs/report/sections/03_设计方案.md   # 仅 3.4 小节
```

### 5.3 本地合并与生成 Word

```bash
# 1. 生成示意图（架构图、流程图、测试/RAG 指标图）
python docs/report/build_figures.py

# 2. 合并章节，生成 Markdown 版
python docs/report/merge_report.py

# 3. 按学校模板生成 Word 版
python docs/report/build_docx.py
```

脚本会按章节顺序生成：

```text
docs/report/DecisionJury_小学期实验报告.md
docs/report/DecisionJury_小学期实验报告.docx
```

`merge_report.py` 会自动从章节标题生成 Markdown 分级目录，并统计仍未清理的占位符数量；`build_docx.py` 会保留封面和成绩页，替换模板示例正文，写入 Word 目录域（打开文档或更新域时生成带页码的分级目录），并把图表、表格和代码块排版进 Word。

> 如果生成时目标 docx 正在 Word 中打开，脚本不会覆盖它，而是把新版本写成
> `DecisionJury_小学期实验报告_含目录.docx`。关闭 Word 后重新运行
> `python docs/report/build_docx.py`，或用新文件替换旧文件即可。

### 5.4 提交 PR

- 分支命名：`feature/report-<章节名>`。
- PR 标题：`docs: write report section <章节名>`。
- PR 描述：说明改动的章节、覆盖模块、截图/数据来源、未完成事项。
- 合并前由组长检查：所有 `【待填写】` 是否已清理、是否与真实代码/测试结果一致。

### 5.5 合并到 Word 模板

当前仓库已经提供自动生成脚本，优先使用脚本生成，再由组长做最终排版检查：

```bash
python docs/report/build_docx.py
```

> 重要：原始模板文件 `小学期实验报告模板(1).docx` 不会被修改。`build_docx.py` 只读取仓库内副本
> `docs/report/templates/小学期实验报告模板.docx`，并把结果写到
> `docs/report/DecisionJury_小学期实验报告.docx`；脚本会拒绝把输出路径写成模板路径。
> 如果学校模板有更新，请手动替换 `templates/` 下的副本，不要改动原始文件。

生成的 `docs/report/DecisionJury_小学期实验报告.docx` 已经保留学校模板的封面和成绩页，并替换为报告正文。生成后仍需人工完成以下检查：

1. 打开 `docs/report/DecisionJury_小学期实验报告.docx`，填写封面中的班级、专业、学号、姓名。
2. 把正文中的 `【截图：...】` 替换为真实运行截图（创建案件、多轮对话、庭审回放、判决书、执行轨迹、观察清单、工具日志、RAG 结果等）。
3. 按模板要求核对字体和排版：
   - 正文：五号宋体，首行缩进 2 字符；英文与数字使用 Times New Roman。
   - 标题：宋体加粗，数字与汉字之间空两格。
   - 图表：先插入正文，再添加表题/图题，并在正文中引用（“如表 1 所示”“如图 1 所示”）。
   - 公式：使用 MathType 6.0 以上版本录入，编号用（1）（2）……
4. 目录页已插入 Word 目录域：打开文档后如目录未自动生成，右键目录 → “更新域” → “更新整个目录”，即可得到带页码的分级目录。
5. 删除模板中残留的说明性文字和“参考目录（提交时请删除该内容）”。
5. 组长统一 Word 样式、图表编号和参考文献格式后定稿。

## 7. 写作注意事项（遵守 AGENTS.md）

- 不编造：功能、测试数据、RAG 命中、工具结果必须与当前代码/实际运行结果一致。
- 截图要求：使用真实运行截图；截图需清晰，展示关键页面或调用过程。
- 引用规范：正文引用图/表/参考文献要在文中写出编号。
- 范围一致：报告只描述 `docs/01_MVP.md` 范围内的购物决策；时间决策主流程属于延期范围，不能写成已完成；医疗、法律、投资等高危场景只作为“边界/拒绝处理”描述。
- 完成标准：每个章节提交前自行通读，确认无占位符、无错别字、格式符合模板。
